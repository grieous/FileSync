# WinSync v0.4 需求与实施计划

四条需求，按「风险 × 收益 × 依赖」排优先级。原则：先做**可验证**的（有测试、有基准），再做**可见**的（界面、托盘），最后做**结构性的**（界面信息架构）。

## 优先级总表

| 优先级 | 需求 | 为什么这个顺序 | 验收方式 |
|---|---|---|---|
| **P0** | 哈希缓存（path + mtime + size → 复用 hash） | 纯后端、可单测、可基准；做完后轮询成本降两个数量级，也是后面提高触发频率的前提 | 单元测试 + 3000 文件冷/热扫描基准 |
| **P1** | 程序图标（窗口 / 任务栏 / 托盘 / exe 文件） | 独立、改动小、立刻可见；托盘依赖它 | 编译后检查 PE 资源 + 视觉确认 |
| **P2** | 托盘进程（关窗口不退出、右键菜单） | 与 P1 同一套代码；但「关窗口隐藏」涉及窗口生命周期，风险高于纯图标 | 手动：关窗口后进程仍在、菜单可用 |
| **P3** | 界面完全对齐飞牛同步 + 配置留在界面 | 工作量最大、不确定性最高（拿不到客户端像素，只能对齐信息架构与设计系统） | 视觉检查 + 功能回归（同步/记录/日志） |

先把 P3 的不确定点说清楚：**飞牛同步的 Windows 客户端是 Tauri 闭源包，我无法截屏**（安全策略禁止启动进程与运行时编译 .NET）。能拿到的是它 Web 端的真实产物：`/fn-sync/` 的 CSS/JS。所以「完全照做」的落点是：

- **设计系统**：Semi Design（字节）——主色 `--semi-brand-5`、圆角 6/12px、neutral 灰阶、14px 正文
- **信息架构**：任务卡（本机目录 ⇄ 目标）＋ 状态/进度 ＋ 记录（文件级）＋ 设置（模式、过滤）
- **交互**：设置默认折叠、关键操作用主按钮、失败给可执行的原因

不能保证像素级一致，保证结构与观感一致。这一条需要你验收时确认。

## P0 哈希缓存

**问题**：`scan_with` 对每个文件无条件 `hash_file`，而 GUI 每 30 秒轮询一次 —— 10 GB 目录 = 每 30 秒读 10 GB。

**方案**：状态库新增 `hash_cache(path, size, mtime_ns, blake3)`；扫描时大小与纳秒级 mtime 都相同则复用哈希，不读文件。

**为什么用纳秒 mtime**：秒级精度下，"同一秒内改两次且大小不变"会漏判。纳秒精度把窗口压到几乎不可能。仍保留一个理论漏洞：文件被改成同样大小、且 mtime 被刻意还原——这属于人为构造，不在防护范围（真需要可以再校验采样块）。

**失效规则**：
- 大小或 mtime 变了 → 重算
- 路径不在新缓存里（被删除/被过滤）→ 从缓存表移除（整表替换）
- 扫描后立刻回写，即使会话因对端离线失败也保留

**验收**：单测覆盖"冷→热→改内容"三段；基准 3000 文件对比耗时；热扫描的 `root_hash` 必须与冷扫描一致。

## P1 程序图标

四处都要：

| 位置 | 实现 |
|---|---|
| exe 文件（资源管理器） | `winres/app.ico` + `version.rc` 的 `ICON` 资源，`build.rs` 已能调 SDK 的 `rc.exe` |
| 窗口/任务栏 | `egui::IconData`（RGBA） |
| 托盘 | `tray_icon::Icon::from_rgba` |
| 关于/标题栏 | 文本，无需图片 |

图标设计：Semi 主色蓝底圆角方块 + 白色上下双箭头（同步语义），16/32/48/64/128/256 多尺寸。**程序内与 exe 资源用同一套绘制参数**，避免两处观感不一致。

## P2 托盘进程

行为定义：

- 关窗口 → **隐藏到托盘**，进程继续同步（这是一个同步工具的默认预期）
- 托盘菜单：`打开主界面` / `立即同步` / `暂停自动同步` / `退出`
- 双击托盘图标 → 打开主界面
- 退出必须走菜单，避免用户以为"关了窗口就退了"——首次隐藏时在日志里写一条说明

风险与对策：托盘创建失败（无桌面会话、权限异常）时**降级为普通窗口程序**，不能因为托盘挂了导致程序打不开。

## P3 界面重构

结构（对齐飞牛同步）：

```
┌──────────────────────────────────────────────┐
│ WinSync   ● 正常   上次 19:20    [设置] [同步] │  ← 顶部：状态 + 主操作
├──────────────────────────────────────────────┤
│ ┌ 任务卡 ──────────────────────────────────┐ │
│ │ D:\Sync  ⇄  192.168.3.222:18443 · 房间 default │
│ │ 双向同步 · 忽略 .git / *.lnk              │ │
│ │ [进度条 / 上次结果：推送 2 拉取 1 删除 0]  │ │
│ └──────────────────────────────────────────┘ │
│  记录 / 日志  ← 二级标签                      │
└──────────────────────────────────────────────┘
```

要点：

1. **状态前置**：颜色点 + 一句话结论（正常 / 同步中 / 有错误 / 尚未同步），不用用户读日志
2. **任务卡**：一眼看清"哪两个位置在同步、什么模式、什么规则"
3. **设置收进折叠区**：服务器、密钥、房间、目录、模式、过滤，默认收起，减少首屏噪音
4. **配置仍在界面**：所有配置项可编辑、可保存；`config.json` 只是持久化载体，不是唯一入口
5. **失败要能动手**：错误文案带下一步（例："两端过滤规则不一致 → 把两台设成一样"）

配色（取自其 CSS 变量）：

| 用途 | 值 |
|---|---|
| 主色 / 主按钮 | `#2173DF`（brand-5） |
| 页面背景 | `#FFFFFF` / 次级 `#F7F8FA` |
| 正文 / 次要文字 | `#1C1F23` / `#6B7280` |
| 边框 | `#E5E7EB` |
| 成功 / 危险 | `#00B42A` / `#F53F3F` |
| 圆角 | 卡片 12px，控件 6px |

## 实施顺序与验证

1. P0 → `cargo test` + 基准数据
2. P1 → 编译通过 + 检查 exe 资源段含图标
3. P2 → 编译通过；手动确认关窗口后进程存活
4. P3 → 编译通过；手动走一遍同步/记录/日志

每步独立提交，避免一次改太多导致无法定位问题。
